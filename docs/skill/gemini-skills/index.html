Gemini Skills 撰寫與格式規範

在蛋蛋村的技術演進中，Skill (技能) 是 AI 助手的靈魂。本篇將詳細拆解 Gemini Skills 的標準結構，讓你能夠精準地為 AI 注入特定領域的知識。

1. 核心結構概觀​

一份標準的 Gemini Skill 由 YAML 元數據 (Front Matter) 與 指令說明 (Instructions) 組成。這兩者共同構成了 Skill 的「基因」。

1.1 YAML 元數據 (Front Matter)​

位於檔案最上方，使用 --- 隔離。包含 Skill 的基本標識：

  • id: 唯一的 ID (建議使用小寫與連字號，如 my-awesome-skill)。
  • name: 顯示名稱。
  • description: 簡短的功能描述。

1.2 指令說明 (Instructions)​

這是 Skill 的主體，通常包含：

  • 角色設定：定義 AI 的身份。
  • 寫作任務：明確 AI 該做什麼。
  • 發文路徑/規範：技術性的細節與檔案存放規則。
  • 操作指南 (檢核表)：要求 AI 在產出完成後顯示檢核表供使用者確認（不應包含在產出檔案內）。

2. 格式規範與範例​

為了讓 AI 能正確解析，我們必須嚴格遵守以下格式。

2.1 標準代碼範本​

---
id: [your-skill-id]
name: [Skill Name]
description: [Brief description]
---

# 角色設定
你是一位[職位/角色]，精通[領域]...

# 寫作任務
根據資料產出[目標內容]...

# 格式規範
1. **[規範 1]**...
2. **[規範 2]**...

# 操作指南 (請在產出完成後，於對話框中獨立顯示供使用者確認，不要寫入檔案內)
- [ ] [檢核項 1]
- [ ] [檢核項 2]

# 參考資料
[提供背景資訊的預留區]

3. 撰寫要點 (技術史官的建議)​

3.1 職責邊界清晰​

不要試圖讓一個 Skill 處理所有事情。例如 egg-village-news-reporter 就專注於新聞，而 egg-village-finance-analyst則專注於金融數據。

3.2 結構化輸出 (檢核表)​

在指令末尾包含一個「操作指南」區塊，要求 AI 產出文章後顯示檢核表。這能極大地降低 AI 產出錯誤的機率，且不會污染最終的文章內容。

3.3 視覺化引導 (Mermaid)​

若 Skill 涉及複雜的邏輯或流程，可以在規範中要求 AI 使用 mermaid 語法進行視覺化展現。
